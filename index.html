What every project must have

Your bot can be about anything useful. These seven parts are the same for everyone, and your project is graded by them.

7 must-have elements

  1. 1User Input. The bot receives data: a button, a command, text or a number.
  2. 2Data Processing. Make.com uses the data: searches, compares, counts, saves.
  3. 3Decision Making. A Router or Filter chooses what happens.
  4. 4Data Storage. Data is saved outside Telegram, for example in Google Sheets.
  5. 5Automation. One user message starts several connected actions.
  6. 6User Feedback. The bot replies with a real result, not fixed text.
  7. 7Validation. Wrong or missing input gets a helpful message.
AI is optional. Automation is mandatory.
  • At least 5 meaningful modules. More modules do not give more points.
  • Not only Telegram → Telegram. Connect Google Sheets or another service.
  • No static bots and no copied tutorials.
  • If you use AI, it does one specific job (classify, summarise, check an answer).
  • Never share your bot token, API keys or passwords.
  • You must be able to explain every module you use.

The workflow every bot follows

Telegram user→Trigger→Router / Filter→Sheets / API / AI→Storage→Bot reply

Choose your idea

Goal: your own problem and your own users. You decide what the bot does.

Think it through

  1. What do people around you still do by hand, on paper or in a messy chat?
  2. Who exactly will use the bot? “Grade 10 students” is better than “everyone”.
  3. What will the user send: a button, a word, a number?
  4. What will Make.com check or decide?
  5. What will be saved in the sheet, and what will the user get back?

Your idea is ready if…

  • a real person would use it more than once;
  • the bot does more than send the same fixed text;
  • something is saved and something is checked;
  • a wrong input is possible, and you know what the bot will reply;

Build the bot, the sheet and the scenario

Goal: a working scenario with at least 5 meaningful modules, including a route for wrong input. No code: you only click data bubbles.

2a. Create the bot

  1. In Telegram open @BotFather and send /newbot.
  2. Choose a name and a username ending in bot.
  3. Copy the token and paste it only into the Make.com connection.

Keep the token secret. If it appears in a screenshot or video, send /revoke to @BotFather and make a new one.

2b. Create the Google Sheet

Row 1 holds clear column names. One row = one record.

timestampusernamechat_iditemstatus

Save chat_id: it lets you find each user’s own records.

2c. Map data with bubbles

Click Run once and send a message to your bot. Now every field in the next modules shows the data from Telegram as purple bubbles. Click a field, then click a bubble. That is all the “programming” you need.

Field “Text” in Send a Text Message

Booked! Free kits before you:4. free. Item:1. Message: Text

Field “Chat ID”

1. Message: Chat: ID

2d. Build the scenario

  1. Telegram Bot · Watch Updates: the trigger. Starts the scenario when a message arrives.
  2. Router: one route per situation. Always add a fallback route for wrong input.
  3. Google Sheets · Search Rows: check existing data (free places, duplicates, the user’s records).
  4. Google Sheets · Add a Row: save the new record.
  5. Telegram Bot · Send a Text Message: reply with the result. Add buttons in Reply markup.

How to check a test

  1. Send the message in Telegram.
  2. In Make.com open History and click the run. Check each module’s input and output bubbles.
  3. Open the Google Sheet: is the row there and correct?
  4. Read the bot’s reply: does it use the data?

Try to break your bot

Send a sticker, letters instead of a number, a very long text and the same message twice. A good bot answers every one of them clearly and saves nothing wrong.

“Fail → fixed → Pass” is a good result. It shows you tested and improved your work.

Submit your project

Goal: one complete submission through the Google Form. Prepare the links before you open it.

The form asks for

  • Bot username: @your_bot
  • Short description: problem and users
  • Link to your filled-in documentation
  • Link to your demo video (1–2 min)

Before you press Submit

  • The documentation has both screenshots and the test table.

Never submit tokens, API keys or passwords. Your teacher tests the bot from Telegram and does not need them.

Practise these teacher questions
  • What happens first after the user sends a message?
  • Why did you use a Router here? How many routes are there?
  • What happens if the user enters wrong data?
  • Where is the data stored? Why these columns?
  • Which value in the reply comes from your data, not fixed text?
  • What would happen if Google Sheets was unavailable?
  • Which part of your project is actually automated?
  • Can you change the reply text or a filter right now?

Have a backup. If the internet fails during the presentation, show your demo video.
